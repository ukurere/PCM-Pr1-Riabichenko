Дисципліна «Методи паралельних обчислень», КНУ ім. Тараса Шевченка, ФКНК.
Виконала: Рябіченко Є.

## Структура

```
src/
  common/          спільний код для всіх версій
    corpus.*       читання каталогу в пам'ять, нумерація документів
    tokenizer.*    нормалізація тексту (UTF-8, нижній регістр, токени ≥ 3 символів)
    index.h        структура зворотного індексу
    output.*       сортування та запис вихідного файлу
    cli.*          розбір аргументів командного рядка
    timer.h        вимірювання часу
  versions/        V0 – V4
  main.cpp         точка входу invidx
  false_sharing/   окрема програма дослідження хибного розділення
scripts/           Python: підготовка корпусу, перевірка, бенчмарки, графіки
results/           results.csv, графіки
report/            звіт (PDF)
data/              дампи та корпуси текстів (не входять до архіву)
```

## Залежності

- C++17-компілятор із підтримкою `std::thread` (перевірено: MinGW-w64 g++ 8.1.0, posix threads)
- `mingw32-make` / `make` або CMake ≥ 3.13
- Python ≥ 3.10, пакети з `requirements.txt`: `pip install -r requirements.txt`

## Збирання

Через Makefile:

```
mingw32-make
```

Параметри компілятора: `-std=c++17 -O2 -Wall -Wextra -pthread`, компонування: `-pthread`.
Імена файлів корпусу мають складатися з ASCII-символів.

Або через CMake (Release):

```
cmake -S . -B build -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

## Запуск

```
build\invidx --mode v3 --threads 8 --k 256 --input data\corpus_en --output out\v3.tsv
```

## Корпус

Англійська Вікіпедія, перша частина дампу `enwiki-latest-pages-articles1.xml-p1p41242.bz2`
(dumps.wikimedia.org, 299,6 МБ). Після очищення вікі-розмітки — 216 файлів, 220,4 МБ, 9 752 статті:

```
python scripts/prepare_corpus.py --dump data\enwiki-p1p41242-full.bz2 --dst data\corpus_en --prefix en --target-mb 220
```

| Аргумент | Значення | За замовчуванням |
|---|---|---|
| `--mode` | `v0`, `v1`, `v2`, `v3`, `v4` | `v0` |
| `--threads` | кількість потоків P | `1` |
| `--k` | кількість блокувальних змінних (лише V3) | `256` |
| `--merge` | спосіб злиття (лише V4): `seq` або `tree` | `tree` |
| `--input` | каталог із текстовими файлами | обов'язковий |
| `--output` | шлях до вихідного файлу індексу | обов'язковий |

Програма друкує в stdout рядок із часом фаз (мс):
`read_ms=... compute_ms=... write_ms=... total_occurrences=...`

Дослідження хибного розділення:

```
build\false_sharing --threads 4 --impl B --reps 5
build\false_sharing --threads 8 --pad 32 --reps 5
build\false_sharing --info
```

| Аргумент | Значення | За замовчуванням |
|---|---|---|
| `--threads` | кількість потоків P | `1` |
| `--impl` | `A` — `int64_t counters[P]`, `B` — `struct Padded { int64_t value; char pad[56]; }` | — |
| `--pad` | довільний заповнювач: `0`, `8`, `24`, `32`, `56` байтів (замість `--impl`) | — |
| `--iters` | кількість інкрементів на потік | `10000000` |
| `--reps` | кількість вимірюваних прогонів (після одного попереднього) | `5` |
| `--info` | надрукувати розмір рядка кешу L1 і кількість логічних процесорів | — |

## Формат вихідного файлу

```
слово<TAB>загальна_кількість<TAB>doc17:12,doc3:5,doc41:1
```

Рядки впорядковано за словом (за байтами UTF-8); записи в рядку — за спаданням кількості,
за однакової кількості — за зростанням номера документа.
Документи нумеруються з 0 у порядку сортування імен файлів.

## Нормалізація тексту

Літера — символ категорії Unicode `L*`, цифра — `Nd`; нижній регістр — простий
(односимвольний) переклад. Таблиці `src/common/unicode_tables.h` згенеровано скриптом
(потрібен лише за зміни правил):

```
python scripts/gen_unicode_tables.py
```

Наслідки правил: звичайний (`'`) і типографський (`’`) апострофи є роздільниками
(«п'ять» → «ять»), а `ʼ` (U+02BC) — літера; комбінований наголос (U+0301) розриває слово.

## Перевірка коректності

Виходи V2, V3 (усі K) і V4 (seq, tree) за P = 1, 2, 4, 8 порівнюються побайтово з V0;
V1 запускається довідково. Звіт — `results/verify.txt`, код завершення 1 у разі розбіжності.

```
python scripts/verify.py
```

## Вимірювання

Перед запуском: закрити сторонні застосунки, підключити живлення, увімкнути режим
«Максимальна продуктивність».

```
python scripts/bench.py
```

- спершу один попередній прогін кожної конфігурації (до результатів не входить), далі 5 повторень;
  повторення чергуються по колу між конфігураціями, між запусками пауза 2 с;
- `compute_ms` — лише побудова індексу (для V4 — разом зі злиттям, яке також окремо в `merge_ms`),
  без читання файлів і запису результату;
- результати: `results/results.csv`, `results/false_sharing.csv`, конфігурація системи —
  `results/system_info.txt`;
- `--only v3,fs` — перезапустити лише частину, `--append` — дописати до наявних CSV.

## V1 і розподіл частот слів

```
python scripts/v1_runs.py      # 10 запусків V1 за P = 8 → results/v1_runs.csv, results/v1_lost_words.csv
python scripts/zipf_top20.py   # частка 20 найчастотніших слів → results/zipf_top20.csv
```

`zipf_top20.py` читає вихідний файл V0 (`out/verify/v0.tsv`, створюється `verify.py`).
